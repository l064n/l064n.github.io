## Overview

Setting up an on-premises multi-GPU compute cluster presents unique challenges that don't exist in cloud environments. This document covers the key optimization strategies I've applied to our heterogeneous setup — RTX 3090s, MI50s, and Jetson AGX Orin nodes — for running large language models entirely locally at my Oakland workspace.

## Hardware Topology

The current configuration uses four dual-GPU nodes connected via a dedicated 10GbE switch:

```
Node A (RTX 3090 ×2) ──┐
                        ├── 10GbE Switch ─── Management Station
Node B (MI50 ×2)       ──┘                      (Proxmox Host, M1 Max via Rosetta)
Node C (Jetson AGX Orin) ──┐
                            ├── Edge Inference Cluster
Node D (RTX 3090 ×2)      ──┘
```

Each node runs a headless Ubuntu 24.04 LTS installation with GPU passthrough through Proxmox VE containers. The management station handles orchestration via Docker Compose and vLLM serving endpoints.

## Thermal Management

The biggest bottleneck in sustained inference workloads is thermal throttling. Stock coolers on RTX 3090 cards max out around 82°C under continuous load, which triggers clock speed reductions after approximately 45 minutes of operation.

### Custom Cold Plate Solution

I designed and printed a series of cold plates using SLA resin with embedded copper heat spreaders:

```python
# Thermal monitoring script (runs every 30s via cron)
import subprocess
import json
from datetime import datetime

def read_gpu_temps():
    result = subprocess.run(
        ["nvidia-smi", "--query-gpu=temperature.gpu,utilization.gpu,power.draw",
         "--format=csv,noheader,nounits"],
        capture_output=True, text=True
    )

    temps = []
    for line in result.stdout.strip().split("\n"):
        temp, util, power = [float(x) for x in line.split(",")]
        temps.append({
            "temp_c": round(temp, 1),
            "util_pct": int(util),
            "power_w": round(power, 1),
            "timestamp": datetime.now().isoformat()
        })

    return temps

# Alert threshold: 75°C sustained for >60 seconds
```

## ROCm on MI50 Nodes

Getting AMD's ROCm stack working on consumer hardware requires some surgical tweaks. The MI50s (polaris architecture) aren't officially supported in ROCm 5.x, but with a device ID override:

```bash
# /etc/modprobe.d/amdgpu.conf
options amdgpu ppfeaturemask=0xffffffff
```

After flashing a modified VBIOS and adding the `amdgpu.si_support=1` kernel parameter, the MI50s show up as supported devices under ROCm 4.5 with full HIP acceleration.

## Key Takeaways

- **Heterogeneous clusters** require careful workload routing — NVIDIA GPUs handle vLLM serving while AMD nodes take on batch embedding generation
- **Jetson AGX Orin** excels at edge inference (70W TDP ceiling) but struggles with context windows >8K tokens
- **Custom cooling** is non-negotiable for sustained workloads — stock coolers will throttle within 45 minutes

<Callout type="warning">
High-voltage equipment and custom cooling modifications carry inherent risks. Always disconnect power before working on GPU nodes and ensure proper grounding procedures are followed.
</Callout>
